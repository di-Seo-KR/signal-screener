## TL;DR — 가장 먼저 봐주실 핵심 결론

1. **현재 화면 25개는 너무 많다.** 정보 구조를 3-탭 (분석 · 운영 · 정보) 으로 그룹화해서 인지부하 −40% 를 노린다.
2. **홈은 "투자 입문자가 첫 5분에 무엇을 해야 하는가" 라는 답을 못 주고 있다.** Hero 카드 1개를 "오늘 할 일 3가지" 액션 위주로 재설계해야 함.
3. **자동매매 / 실거래 가 사실상 동일 컨셉인데 두 탭으로 쪼개져 있어 새 사용자가 길을 잃는다.** "운영" 으로 통합하고 내부 segmented (모의 / 실거래) 로 분리.
4. **핵심 액션 (자동매매 시작 / 긴급정지) 의 모바일 클릭 거리가 너무 멀다.** PrimaryAction 도크 패턴 도입 권고.
5. **즉시 진행 top 5 (3-7장 참고)**: ① 통합 알림 센터 ② 봇 리더보드 (익명) ③ 포트폴리오 분석 페이지 ④ 백테스트 비교 뷰 ⑤ 입문자 온보딩 5스텝.

## 1. 현재 화면 UX Audit (화면별)

각 화면당 5개의 기준 (첫인상 / 정보 위계 / 인지 부하 / 클릭 거리 / 상태 명확성 / 에러 처리) 으로 평가하고, 3~5개 구체적 개선점 + before/after 를 제시한다.

### 1-1. 홈 (`tab === "home"`, `src/App.jsx:7315~9367`)

**첫인상**: 로그인 사용자에겐 그리팅 + 🔥 스트릭 → 마켓 브리핑(6 지수) → 핫 종목 → 시그널 피드. 비로그인은 "AI가 찾아주는 최적의 매수 타점" hero. 카드가 7~10개 길게 늘어선다.

**정보 위계 문제**:
- "오늘 무엇을 해야 하는가" 라는 액션 가이드가 부재. 마켓 브리핑은 정보 carousel 일 뿐, 사용자가 다음에 클릭할 곳을 알려주지 않는다.
- 스트릭 카드가 가입 직후엔 "1일 연속" 로만 보이는데 이게 왜 중요한지 설명이 없다. 이탈 유발.
- 비로그인 hero 의 CTA "무료 가입하기" / "둘러보기" 가 모두 평이. Toss 라면 "어떤 종목이 오를지 무료 진단 받기" 같은 즉시 가치 카피.

**인지 부하**: 스크롤 7~10번. 모바일에서 fold 1 안에 들어가는 것은 그리팅 + 스트릭 + 마켓 브리핑 헤더 정도. 핵심 가치가 fold 1 에 없다.

**클릭 거리**:
- 자동매매 ON 까지: 홈 → 하단 탭 "AI매매" → 봇 선택 → 설정 → ON. **4 클릭**.
- 스크리너 결과 → 자동매매 봇 추가까지: 현재 **불가능** (직접 연결되지 않음).

**상태 명확성**: ◯ 마켓 브리핑 LIVE 뱃지는 좋음. △ 핫 종목 변화율은 명확하나 "이게 사도 되는 종목인가"는 안 보여줌.

**에러 처리**: 마켓 데이터 fetch 실패 시 skeleton 만 무한 표시. "실패 → 재시도" 버튼 없음 (`App.jsx:7540~7558` 부근).

**개선점 5개**:

1. **[7315] Hero 카드를 "오늘의 액션 3" 으로 재설계** (S 1일)
   - Before: 그리팅 → 스트릭 (정적)
   - After: 그리팅 안에 chip 3개. 예: ① "어제 시그널 12개 점검하기" ② "내 봇 수익률 +2.3% 확인" ③ "S&P 500 −1.2% — 포트폴리오 리스크 점검". 클릭 → 해당 탭 deeplink.
   - 비로그인은: "지금 매수 타점인 종목 3개 무료 진단" (가입 walls).

2. **[7444] 마켓 브리핑 카드 옆에 "내 포트폴리오 임팩트" 미니 패널 추가** (M 3일)
   - Before: S&P 500 +0.5%, NASDAQ −0.3% (글로벌 정보만)
   - After: 카드 하단에 "→ 내 포트폴리오 추정 변화 +$23.40 (+0.6%)". 비로그인은 "포트폴리오 등록 시 자동 계산" CTA.

3. **[7412] 모바일 빠른 접근 6개 버튼 (icon row) 을 4개로 줄이고 라벨 가독성 개선** (S 1일)
   - Before: 6개 icon 가로 스크롤 (스크리너/AI매매/전략분석/뉴스/캘린더/백테스트)
   - After: 4개 핵심 (스크리너/AI매매/포트폴리오/알림). 나머지는 "더보기" 시트로. font-size 12 → 13, gap 6 → 8.

4. **[7307] PullToRefresh 실패 fallback 추가** (S 0.5일)
   - Before: fetch 실패 시 silent
   - After: Toast `네트워크가 잠시 끊겼어요 — 다시 시도하기` (action 버튼).

5. **로그인 직후 onboarding tour 도입** (M 3일 — 7장 spec 참고)
   - Before: 가입 직후 홈 그대로 노출
   - After: 5스텝 walkthrough (① 봇 선택 ② 모의실행 ③ 시그널 보기 ④ 알림 설정 ⑤ 포트폴리오 등록).

### 1-2. 자동매매 (`tab === "auto-trading"`, `src/AutoTrading.jsx`)

**첫인상**: 4개 봇 카드 (안정형/균형형/공격형 + BTC 자동매매). 각 카드에 승률 / Sharpe → "안정성 등급(S~D)" / MDD / 12개월 에쿼티 곡선 미니차트.

**정보 위계 문제**:
- 4개 봇이 horizontally equal weight 으로 노출 → 입문자는 "내게 맞는 봇이 뭐지" 결정 불가. **추천 봇 1개 + 비교 보기 2개** 구조가 더 친화적.
- "안정성 등급 S/A/B/C/D" 는 2026-05-09 도입돼서 좋으나, 등급 옆 무슨 기준인지 hover 만 가능. 모바일은 tap 필요한데 발견성 낮음.

**인지 부하**:
- "예상 수익 8-15%" 라는 표기가 백테스트 기반인지 실제 운영 기반인지 모호. 한국 금융감독원 가이드라인 관점에서도 위험 (사업기획 영역 — PLAN-BIZ 와 협업).

**클릭 거리**: 봇 시작까지 봇 카드 클릭 → 설정 → 시작 = 3 클릭. 합격선.

**상태 명확성**: ◯ 현재 운영 중 봇은 명확. △ "지금 봇이 무엇을 보고 있는지" 는 안 보임 (시그널 워치리스트는 RealTrading 에만 있음 — `dashboard-widgets.jsx:6` SignalWatchlist).

**에러 처리**: 봇 활성화 API 실패 시 toast 만. "왜 실패했는지" 사용자가 알 수 있는 가이드 부재.

**개선점 5개**:

1. **[AutoTrading.jsx:164] 봇 추천 알고리즘 + Quiz onboarding** (M 3일)
   - Before: 4봇 동등 표시
   - After: 첫 진입 시 3문항 quiz (자본 / 위험성향 / 목표 수익률) → 추천 봇 highlight + 비교 봇 2개 chip 으로.

2. **각 봇 카드에 "지금 이 봇이 보고 있는 종목 3개" 미니 워치리스트** (M 3일)
   - 사용자 신뢰 = "투명성". 봇이 실제로 무엇을 모니터하는지 안 보이면 black box.
   - API: `/api/real-trading/signal-watchlist?botId={id}&limit=3` 신설 또는 기존 endpoint 확장.

3. **봇 카드에 "최근 30일 거래 N건 / 승률 %" 실시간 메트릭 표기** (S 1일)
   - 현재는 백테스트 stats 만. 실제 운영 stats 도 같이 노출하면 사용자 의사결정 quality 상승.
   - 데이터 source: `bot-performance.js` 활용.

4. **"안정성 등급" tooltip 모바일 발견성 개선** (S 0.5일)
   - Before: ⓘ icon hover 만, 모바일은 tap. 발견 어려움.
   - After: 등급 라벨 자체를 tappable 영역으로. 추가로 봇 카드 하단에 1줄 설명 "Sharpe 1.8 → A등급" 같이 풀이.

5. **봇 활성화 실패 가이드 카드** (S 1일)
   - Before: Toast "활성화 실패"
   - After: Dialog 로 원인 분기 — ① Binance API 키 미연결 → 연결 CTA ② 자본 부족 → 입금 가이드 ③ 한도 초과 → 한도 설명.

### 1-3. 실거래 관제센터 (`tab === "real-trading"`, `src/RealTrading.jsx`)

**첫인상**: 보유자산 hero (큰 $) + 4개 메트릭 (일손익/MDD/진행거래/연속손실) + 매매 제어 (시작/중지/일시정지/긴급정지) + 7개 위젯 (자산곡선/라이브메트릭/포지션도넛/거래내역/일별히트맵/시그널워치리스트/시스템상태).

**정보 위계 문제**:
- 시니어 트레이더 관점에선 ◯ 최적. 입문자 관점에선 정보 과부하.
- 4개 메트릭 라벨이 영문 약어 (MDD) + 한국어 혼재. "최대 낙폭 -8% (지금까지 가장 크게 잃은 비율)" 식 1줄 설명이 hint 만 있음.

**인지 부하**:
- Pro 밀도일 때 한 화면에 17개 카드 (hero+4+control+7+...). 입문자가 보면 패닉.
- 다행히 `density` 토글 있음 (`RealTrading.jsx:101`). 기본값 `"pro"` — 입문자 기본값은 `"simple"` 가 맞음.

**클릭 거리**: 긴급정지까지 1 클릭 (Hero 바로 아래 control panel). 합격. ◯

**상태 명확성**: ◎ "✓ 실거래 중" / "⊙ 대기 중" Badge 명확.

**에러 처리**: status fetch 실패 시 `setError(...)` 만. 화면에 error banner 노출 부재 (위쪽 toast 만).

**개선점 5개**:

1. **[RealTrading.jsx:101] 첫 진입 사용자는 density 자동으로 "simple" 로 시작** (S 0.5일)
   - Before: localStorage 기본값 "pro"
   - After: 신규 사용자 (`localStorage["zepta:rt:firstSeen"]` 없으면) → simple. 3일 사용 후 자동으로 pro 권유.

2. **메트릭 카드 4개에 1줄 카피 추가** (S 0.5일)
   - 위치: `renderMetricCard hint` 부분 (`RealTrading.jsx:502~534`)
   - Before: "한도 -10%" (숫자만)
   - After: "한도 -10% · 이만큼 잃으면 자동으로 매매 멈춰요"

3. **[RealTrading.jsx:589] KPI Bar 상단에 "오늘의 한 줄 코멘트"** (M 2일)
   - Before: 숫자 grid 만
   - After: 상단에 보라색 stripe `📊 오늘은 변동성 폭발 — 봇이 진입 횟수를 평소의 70% 로 줄였어요`. data source = `/api/agents/alpha-lab?market-regime` (QUANT-RES 출력).

4. **"매매 제어 센터" 의 위험 액션을 시각적으로 분리** (S 1일)
   - Before: 시작/중지/일시정지/긴급정지 모두 같은 grid 안.
   - After: 일상 액션 (시작/중지/일시정지) + 위험 액션 (긴급정지) 을 visually divider 로 분리. 긴급정지는 빨간 zone 안에. 2단계 confirm.

5. **시스템 상태 인디케이터 (7번 widget) 를 상단으로 이동** (S 0.5일)
   - Before: 7개 위젯 중 마지막
   - After: hero 아래 stripe 형태. "API 연결 정상 · 마지막 동기화 30초 전". 신뢰성 인식에 직결.

### 1-4. 알파 랩 (`tab === "alpha-lab"`, `src/AlphaLab.jsx`)

**인지 부하**: 비교적 컴팩트 (Card 5~7개). ◯

**개선점 5개**:

1. **[AlphaLab.jsx:129] 최상단에 "오늘의 알파 한줄평" 추가** (S 1일)

4. **promote/demote 이벤트 카드에 "왜" 답변 추가** (S 1일)

## 4. 디자인 시스템 개선 (`src/ui/primitives.jsx`)

### 일관성 점검

| 항목 | 현재 상태 | 개선 |
|------|----------|------|
| **Button variant** | default, primary, success, danger, warn, ghost, outline, subtle, link = 9개 | ◯ 풍부. 단, RealTrading 에서 `linear-gradient` 인라인 스타일이 다수 — `variant="gradient-blue"` 처럼 토큰화 권고 |
| **Button size** | xs(26h), sm(32h), md(38h), lg(44h) | ◯ 잘 분리. 모바일 터치 영역 ≥ 44 만족 (lg) |
| **Card pad** | `pad` prop 으로 자유 (default 18) | ◯. 단, `pad="sm"\|"md"\|"lg"` 토큰화 권고 (현재는 숫자) |
| **Badge tone** | default, blue, green, red, yellow, purple, cyan = 7개 | ◯ |
| **Tabs variant** | underline, pills = 2종 | ◯ |
| **Tooltip** | hover only (mobile 미지원) | ✗ — 모바일 tap 지원 필요. MetricInfo 처럼 click 토글 패턴 표준화 |
| **Modal** | Dialog 단일 컴포넌트 | ◯. 단, BottomSheet 변형 부재 — 모바일 UX 손해 |
| **Toast** | ToastProvider + useToast | ◯ |
| **Skeleton** | 단일 컴포넌트 | ◯ |

### 부족한 컴포넌트 (신규 추가 권고)

1. **`<BottomSheet>`** — 모바일 modal 의 표준. swipe-to-dismiss + drag handle.
   ```jsx
   <BottomSheet open={open} onClose={close} title="필터" snapPoints={["50%", "90%"]}>
     ...
   </BottomSheet>
   ```

2. **`<ActionSheet>`** — iOS 스타일 메뉴 (모바일 길게 누름 → 액션 목록).

3. **`<Stepper>`** — 온보딩 5스텝 / 봇 활성화 6단계 등 진행도 UI.
   ```jsx
   <Stepper steps={["봇 선택", "설정", "모의실행"]} current={1} />
   ```

4. **`<Banner>`** — 페이지 상단 정보 strip (위험 경고 / 새 기능 안내).
   ```jsx
   <Banner tone="warn" icon={<Alert/>} dismissible>
   ```

**라우터 변경 영향도**: 기존 URL 유지 (SEO + 외부 링크 보존) + 그룹 페이지 신규 추가. `validTabs` 는 그대로 두고, 그룹 탭에서 sub-tab 으로 라우팅.

## 7. 모바일 UX 우선순위 (한국 시장 컨텍스트)

한국은 모바일 사용률 75%+ — 모바일 first 가 결정적.

### 7-1. 모바일 GNB 점검

**현재**: 5탭 (홈/스크리너/AI매매/포트폴리오/더보기) `App.jsx:12693`
- ◯ 5개로 적절
- ◯ SVG 아이콘 사용 (이모지 X)
- △ "더보기" 클릭 시 `profile` 로 이동 — 더보기 시트가 아니라 직접 페이지 이동. UX 점프 발생.

**개선**:
- "더보기" 클릭 → BottomSheet 로 카테고리 그룹 (분석 / 정보 / 마이) 표시.
- Sheet 내부에 자주 사용한 탭 3개 highlight (학습됨).

### 7-2. 핵심 액션 모바일 접근성

| 액션 | 현재 클릭 거리 | 권고 |
|------|---------------|------|
| 자동매매 ON | 홈 → AI매매 → 봇 카드 → 시작 = 4 클릭 | ◯ |
| 자동매매 OFF / 긴급정지 | 홈 → AI매매 (또는 실거래) → 제어 패널 = 3 클릭 | ✗ — **PrimaryAction 도크** 권고. 봇이 활성 중이면 화면 어디서나 하단 floating "긴급정지" 버튼 노출. 우상단 alert bell 옆에 작은 STOP icon |
| 알림 확인 | 헤더 알림 아이콘 = 1 클릭 | ◯ |
| 종목 검색 | 홈 헤더 검색바 = 1 클릭 | ◯ |

**제안**: 자동매매 활성 중일 때 모바일 하단 GNB 위에 `40px floating bar` 노출.
```
┌────────────────────────────────────┐
│ 🤖 안정형 봇 운영 중 · +2.3%       │ ← 1번 탭으로 자동매매 화면 진입
│                          [긴급정지]│ ← 2번 탭으로 stop confirm
└────────────────────────────────────┘
```

### 7-3. 카드 레이아웃 모바일 stack 일관성

- 현재 화면별로 grid 처리가 제각각 (`isMobile ? "1fr" : "1fr 1fr"` 패턴 반복).
- **표준화 권고**: `<ResponsiveGrid cols={{ mobile: 1, tablet: 2, desktop: 3 }}>` 컴포넌트.
- 마진 / 패딩도 모바일에선 24 → 16 으로 표준 (현재 일관성 부족 — `padding: isMobile ? "20px" : "28px 32px"` 같은 매직 넘버 다수).

### 7-4. 모바일 폰트 크기

| 영역 | 현재 | 권고 |
|------|------|------|
| 본문 | 14px (`mf(14)`) | 14~15 ◯ |
| 헤딩 H1 | 24~28px | ◯ |
| 헤딩 H2 | 18~20px | ◯ |
| Caption | 10~12px | 11px 이하는 가독성 ✗ — 최소 12 |
| 숫자 (price) | 26~32px | ◯ (큼직) |
| Button | 13~14px | ◯ |

→ tokens.css 의 폰트 토큰 (`--z-font-*`) 활용. 인라인 `fontSize: 12` 같은 매직 넘버 줄여야 함.

### 7-5. 터치 영역

- iOS HIG / Material 권고: ≥ 44x44px
- 현재: 버튼 lg = 44h ◯. md = 38h ✗ — 모바일에서 md 가 너무 작음.
- **표준화**: 모바일에서는 자동으로 size `md → lg` 승급.

### 7-6. 푸쉬 알림 권한 요청 타이밍

- 현재 `alerts` 탭 진입 시 권한 요청 (`App.jsx:11244` 부근).
- ✗ — 사용자가 의도 없이 진입한 경우에도 권한 요청 → 대부분 거절.
- **권고**: 알림 첫 시그널이 생성될 때 inline UI 로 "이 알림을 푸시로 받기" 버튼 → 클릭 시 권한 요청. 컨텍스트 + 동기 명확.
