# Feature Dev — 피처 개발 워크플로우 스킬

## 목적

Zepta 프로젝트에서 새로운 피처를 개발할 때,
에이전트 팀 체계(CLAUDE.md, TEAM_STRUCTURE.md)에 따라 체계적으로 진행합니다.
기획 → 설계 → 구현 → 검증의 전체 라이프사이클을 관리합니다.

## 사전 준비

작업 시작 전 반드시 다음 파일을 읽어 팀 구조와 워크플로우를 파악합니다:
- `CLAUDE.md` — 조직 구조, 행동 규칙, 기술 스택
- `TEAM_STRUCTURE.md` — 각 역할별 상세 책임과 사고 프레임워크
- `AGENT_WORKFLOW.md` — 작업 규모별 에이전트 투입 템플릿

## 작업 규모 판단 기준

### 대규모 (풀 팀 투입 — 7명)
- 새 페이지/화면 추가
- 수익 모델 변경
- 서비스 전략 전환
- 대형 피처 (결제, 소셜, 알림 등)

### 중규모 (개발팀 투입 — 4명)
- 기존 피처 개선
- UI/UX 최적화
- 리팩토링
- 복잡한 버그 수정

### 소규모 (즉시 처리)
- 텍스트/라벨 수정
- 설정값 변경
- 단순 버그 핫픽스

## Phase 1: 전략 수립 (기획 + 마케팅)

대규모 작업 시, 3명의 에이전트를 **병렬**로 투입합니다:

### PLAN-BIZ (사업 기획)
분석 항목:
```
1. 시장 기회: 이 피처가 어떤 시장 니즈를 해결하는가?
2. 경쟁사 분석: Toss, Kakao Pay 등에서 유사 기능은?
3. 유입 전략: 이 피처로 어떻게 사용자를 끌어올 것인가?
4. 수익 모델: 광고, 프리미엄, 제휴 등 어떤 수익이 가능한가?
5. KPI: 성공을 측정할 지표는 무엇인가?
```

### PLAN-SVC (서비스 기획)
산출물:
```
1. 화면 구성: 각 화면의 레이아웃과 컴포넌트 정의
2. UX 플로우: 사용자 행동 시나리오 (Happy Path + Error Path)
3. 정보 구조: 데이터 표시 우선순위, 계층 구조
4. 상태 전이도: 각 화면/컴포넌트의 상태 변화
5. 개발 핸드오프: 컴포넌트 스펙, API 요구사항
```

### MKT-LEAD (마케팅)
분석 항목:
```
1. SEO: 이 피처가 검색 유입에 미치는 영향, 필요한 메타태그
2. 광고: AdSense/쿠팡 파트너스 배치 최적화
3. 유입: 소셜 공유, 바이럴 요소, 커뮤니티 홍보
4. 리텐션: 게이미피케이션, 알림, 습관 형성 요소
5. 데이터: GA4 이벤트 추적 계획, 전환 퍼널
```

## Phase 2: 통합 스펙 확정

3명의 결과를 종합하여 **통합 스펙 문서**를 작성합니다:

```markdown
## 피처: {이름}
### 목표: {한 줄 요약}
### 성공 지표: {KPI 3개}

### 화면 스펙:
- {화면 1}: {설명}
- {화면 2}: {설명}

### 기술 요구사항:
- API: {필요한 API 목록}
- 상태 관리: {localStorage / Supabase / Context}
- i18n: {필요한 키 목록}

### SEO/마케팅 요구사항:
- 메타태그: {title, description, OG}
- 추적 이벤트: {GA4 이벤트 목록}
- 광고 배치: {위치}
```

## Phase 3: 아키텍처 설계 (DEV-ARCH)

통합 스펙을 바탕으로 아키텍처를 설계합니다:

```
1. 파일별 변경 범위 정의
2. 컴포넌트 트리 설계
3. 상태 관리 전략
4. API 연동 설계
5. 경계 사례 목록
6. 리스크 분석
7. 구현 순서 (의존성 기반)
```

## Phase 4: 구현 + QA + 성능 (병렬)

### DEV-IMPL (구현)
- 아키텍처 설계에 따라 코드 작성
- 프로덕션 수준, 접근성, 반응형, i18n
- Zepta 코딩 컨벤션 준수 (C 테마, t() 함수, JSX)

### DEV-QA (품질 검증)
```
□ 기능 정확성
□ 경계 사례 처리
□ 접근성 (ARIA, 키보드)
□ 반응형 (모바일/태블릿/데스크탑)
□ i18n (ko/en)
□ 다크모드/라이트모드
□ 보안 (XSS, 입력 검증)
```

### DEV-PERF (성능)
```
□ 불필요한 리렌더링
□ 번들 사이즈 영향
□ 네트워크 요청 최적화
□ CSS 애니메이션 GPU 가속
□ 메모리 누수 방지
```

## Phase 5: 검증 및 배포

```
1. 라이브 사이트에서 시각적 검증 (Chrome DevTools)
2. 모바일 뷰포트 테스트
3. 다크모드 테스트
4. i18n 전환 테스트
5. Git 커밋 (한국어 존댓말 커밋 메시지)
6. 대표에게 push 요청
```

## 커밋 메시지 규칙

```
feat: {새 기능 설명}
fix: {버그 수정 설명}
style: {UI/UX 변경 설명}
refactor: {리팩토링 설명}
docs: {문서 변경 설명}
perf: {성능 최적화 설명}
```

모든 커밋 메시지는 **한국어 존댓말**로 작성합니다.
